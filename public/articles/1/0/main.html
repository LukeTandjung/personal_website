Prerequisites

Zero Knowledge Proofs (ZKP) are not mathematically trivial. One might balk as to how mathematically dense it could be at times. This albeit terse document aims to hopefully ease this transition slightly.

There are several pure mathematics, mathematical statistics, and theoretical computer science prerequisites needed to understand ZKPs, much less code them. We give the bare minimum background prerequisites for each.

Pure Math

We first define the bare minimum mathematical background to understand Zero Knowledge Proofs (ZKP), by introducing the concept of Groups, Fields, Elliptic Curves, and Bilinear Pairs.

Definition (Binary Operations). A binary operation on a set 𝑋 is a function 𝑋×𝑋→𝑌 assigning 𝑎,𝑏∈𝑋 on element 𝑎∗𝑏, so (𝑎,𝑏)→𝑎∗𝑏.

A good layman example of binary operations is the mathematical operations we are familiar with: +,−,×,÷. Furthermore, we say that a binary operation ∗ is closed on 𝑋 if 𝑎∗𝑏∈𝑋.

Definition (Groups). A group is a set 𝐺 with a closed binary operation ∗ on 𝐺 that satisfies the following properties:

  • ∀𝑎,𝑏,𝑐∈𝐺,(𝑎∗𝑏)∗𝑐=𝑎∗(𝑏∗𝑐) (associative)
  • ∃𝑒∈𝐺 such that ∀𝑔∈𝐺,𝑔∗𝑒=𝑔=𝑒∗𝑔 (identity)
  • ∀𝑎∈𝐺,∃𝑏∈𝐺 such that 𝑎∗𝑏=𝑒=𝑏∗𝑎 (inverse)

A good example of a group is the Rubik cube. We imagine the set 𝐺 of the group as all possible permutations of the Rubik cube, and the binary operation as function compositions 𝑓∘𝑔. Here, we imagine functions 𝑓 and 𝑔 as transformations on the Rubik cube, such as turns on each slice of the cube. Notation wise, we state a group as a tuple (𝐺,∗)

Definition (Abelian). A group 𝐺 is called abelian (or commutative) if ∀𝑎,𝑏∈𝐺,𝑎∗𝑏=𝑏∗𝑎.

With both definitions, we can now concisely define a field.

Definition (Field). A field is a set 𝐹 with binary operations +,× of which

  • (𝐹,+) is an Abelian group with identity 0.
  • (𝐹,×) is an Abelian group with identity 1.

Some example of fields are the real number field ℝ and the complex number field ℂ. For now, we focus on a special field often used in mathematical cryptography, the finite fields of prime order 𝑝. We start by introducing the modulo operator.

Definition (Modulo). We say that 𝑥,𝑦∈ℤ are congruent (or equivalent) in mod𝑛 if 𝑛|𝑥−𝑦, and we write it as 𝑥≡𝑦mod𝑛. So

𝑛|𝑥−𝑦⇔𝑥≡𝑦mod𝑛

For example, 2≡5mod3 because 3|5−2. Similarly, 3≡43mod10 because 10|43−3. Any integer is congruent (mod𝑛) to exactly one integer 𝑥 in the range 0≤𝑥≤𝑛−1.

Definition (Finite Field of Prime Order 𝑝). The finite field of prime order 𝑝, 𝔽𝑝, is the field

𝔽𝑝={0,1,…,𝑝−1}

where 0={…,−𝑝,0,𝑝,2𝑝,…} and 1={…,−𝑝+1,1,𝑝+1,2𝑝+1,…}, and so on. By field definitions then,

𝑎+𝑏=𝑎+𝑏𝑎×𝑏=𝑎𝑏

What we have defined so far are the basic mathematical objects used in a ZKP. Now, we start introducing the fundamental encryption principle that underpins a ZKP, the elliptic curve

Definition (Elliptic Curve) An elliptic curve on field 𝔽 is a smooth curve 𝐸 on (𝑥,𝑦)∈𝔽2 with the relation

𝐸:𝑦2=𝑥3+𝑎𝑥+𝑏

where the discriminant of curve is non-zero (so 4𝑎3+27𝑏2≠0 for 𝑎,𝑏∈𝔽).

The elliptic curve only becomes interesting when you consider it not in a Cartesian geometry space (ℝ𝑛) but in a projective geometry space. The intuition for projective geometry becomes clear when you project a box in ℝ3 in the space:

Imagine you are a single eye in ℝ3 with an unrestricted field of view. Regardless of your exact position in ℝ3,

  1. Every parallel line with the same direction vector will converge to a vanishing point that we call a point of infinity.
  2. All these points of infinity lie on an plane of infinity (in ℝ3), or a line of infinity (in ℝ2). For simplicity, we focus on the ℝ2 case.

We describe the set of all points in the projective geometric space of ℝ2 as ℙ2(ℝ).

In projective geometry, we describe coordinates differently, by using a system of coordinates called homogeneous coordinates. To map from Cartesian coordinates (𝑥,𝑦)∈ℝ2 to homogeneous coordinates (𝑥:𝑦:𝑧)∈ℙ2(ℝ),

(𝑥:𝑦:𝑧)≔(𝑥𝑧,𝑦𝑧,𝑧)

where for 𝑧1,𝑧2∈ℝ\{0},(𝑥𝑧1,𝑦𝑧1,𝑧1)=(𝑥𝑧2,𝑦𝑧2,𝑧2).

Definition (Relation). A relation 𝑅 over a set 𝑋 is a set of ordered pair (𝑥,𝑦) of elements from 𝑋:

𝑅⊆{(𝑥,𝑦):𝑥,𝑦∈𝑋}

The statement (𝑥,𝑦)∈𝑅 reads “𝑥 is 𝑅-related to 𝑦”, and can be written as 𝑥𝑅𝑦, or as 𝑥∼𝑦. Furthermore, a relation is said to be…

  • reflexive if 𝑎𝑅𝑎∀𝑎∈𝑋.
  • symmetric if 𝑎𝑅𝑏⇒𝑏𝑅𝑎,∀𝑎,𝑏∈𝑋.
  • transitive if 𝑎𝑅𝑏∧𝑏𝑅𝑐⇒𝑎𝑅𝑐,∀𝑎,𝑏,𝑐∈𝑋.

Definition (Equivalence Relation). A relation 𝑅 is said to be equivalent if it is reflexive, symmetric, and transitive.

Definition (Equivalence Class). If 𝑅 is an equivalence relation on 𝑋 and 𝑎∈𝑋, the equivalence class of 𝑎 is

[𝑎]={𝑥∈𝑋:𝑎𝑅𝑥}

Definition (Homogeneous Coordinates). Define the equivalence relation 𝑅 over ℝ2\{0⃗} by 𝑎𝑅𝑏 if there exists 𝜆∈𝑅\{0} such that 𝑎=𝜆𝑏. Then,

  • The projective space ℙ2(ℝ) is the equivalence classes [𝑎],∀𝑎∈ℝ2\{0⃗}.
  • For a single equivalence class, 𝑝∈[𝑎] is the homogeneous coordinate of [𝑎].

Under homogeneous coordinates, we can allow a single Cartesian coordinate (𝑥,𝑦) to be represented by infinitely many homogeneous coordinates (𝑥:𝑦:𝑧). While we typically consider the set of all points on the elliptic curve on ℝ

𝐸={(𝑥,𝑦)∈ℝ2:𝑦2=𝑥3+𝑎𝑥+𝑏∧∀𝑎,𝑏,∈ℝ,4𝑎3+27𝑏2≠0},

an interesting property emerges when we consider the elliptic curve in the projective closure.

Theorem (Group Law). Under the projective closure ℙ2(ℝ), which includes the point of infinity 𝑂, the set

𝐸={(𝑥:𝑦:𝑧)∈ℙ2(ℝ):𝑦2𝑧2=𝑥3𝑧3+𝑎𝑥𝑧+𝑏∧∀𝑎,𝑏,∈ℝ,4𝑎3+27𝑏2≠0}⊂ℙ2(ℝ)

forms an Abelian group (𝐸,+) with identity 𝑂, where addition is defined as follows:

  1. For points 𝑃,𝑄∈𝐸, draw a chord (line) connecting 𝑃,𝑄. If 𝑃=𝑄, the resulting line is the tangent line of the elliptic curve.
  2. Extend the line until it intersects with the elliptic curve.
  3. Reflect the point of intersection along the 𝑥-axis. The resulting point is 𝑃+𝑄.

For simplicity sake, we provide a very rough sketch proving this below.

Proof. We show why (𝐸,+) satisfies the properties of the Abelian group:

  • Inverse: The vertical line passing through 𝑃 and −𝑃 meet 𝐸 at 𝑂. Since 𝑂 is unique in ℙ2(ℝ),𝑃+(−𝑃)=𝑂. By reflection, we know that the inverse −(𝑥:𝑦:𝑧) is

    −(𝑥:𝑦:𝑧)=(𝑥:−𝑦:𝑧)
  • Identity: The vertical line passing through 𝑃 and point of infinity 𝑂, has intersection −𝑃. Reflecting the intersected point along the 𝑥-axis gives 𝑃, so by construction, i 𝑃+𝑂=𝑃.
  • Closure: With the addition of 𝑂 to create the projective closure ℙ2(ℝ), 𝐸⊂ℙ2(ℝ) is closed as any line constructing 𝑃+𝑄 has to lie on 𝐸 on 𝑅{2} or 𝑂
  • Commutativity: The lines producing 𝑃+𝑄 is the same as the lines producing 𝑄+𝑃.
  • Associativity: This part of the proof is non-trivial, and is left out. Try constructing an example to see this!

Comment: Under the unique identity lemma, every identity in a group is unique. We can see this under the projective closure ℙ2(ℝ); every point of infinity at each end of every possible line with every possible slope is the same!

Definition (Elliptic Curve Discrete Log Problem). Suppose that for an elliptic curve 𝐸 on 𝔽𝑝, we are given…

  • A base point 𝑃∈𝐸⊂ℙ2(𝔽𝑝)

  • A point 𝑄∈⟨𝑃⟩, so

    𝑄=𝑘𝑃=𝑃+…+𝑃⏟k times

    where ⟨𝑃⟩ is the cyclic subgroup of large prime order |⟨𝑃⟩|=𝑛

Under the Elliptic Curve Discrete Log Problem (ECDLP), we solve for the discrete log 𝑘={0,…,𝑛−1}, which we can also denote as 𝑘=log𝑃𝑄.

There are some unfamiliar terms here. Let’s start with order.

Definition (Order). The order of the group 𝐺 is the number of elements in a group. It is denoted as |𝐺|.

Definition (Cyclic Group). A group 𝐺 is said to be cyclic if it can be generated by some 𝑔∈𝐺. That is, there exists some 𝑔∈𝐺 such that

𝐺={𝑔𝑖:𝑖∈ℤ}

If 𝐺 is cyclic, another notation we can use for it is ⟨𝑔⟩. Furthermore, if |𝐺|=𝑛, then 𝐺={𝑒,𝑔,…,𝑔𝑛−1} - the cyclic group of order 𝑛.

Following all these definitions, we have that

⟨𝑃⟩={𝑂,𝑃,…,(𝑛−1)𝑃}

The idea behind ECDLP is that given a public elliptic curve 𝐸, a public point 𝑃 on it, and a secret 𝑘, it is computationally easy to calculate 𝑄. However, given public 𝐸,𝑃,𝑄, it is computationally infeasible to calculate 𝑘. This is the underlying principle that drives many cryptographic schemes we use today!

Finally we introduce bilinear pairings.

Definition (Pairings). Let 𝐺1,𝐺2 be two additive cyclic groups of prime order 𝑝 and 𝐺𝑇 a multiplicative cyclic group of prime order 𝑝. A pairing is a map 𝑒:𝐺1×𝐺2→𝐺𝑇 satisfying the following properties:

  • Bilinearity: For all 𝑎,𝑏∈𝔽𝑝∗ and 𝑃∈𝐺1,𝑄∈𝐺2, 𝑒(𝑎𝑃,𝑏𝑄)=𝑒(𝑃,𝑄)𝑎𝑏.
  • Non-degeneracy: For all 𝑃∈𝐺1,𝑄∈𝐺2, 𝑒(𝑃,𝑄)≠1.
  • Computability: There exists an efficient algorithm to compute 𝑒.

In general, there are three types of pairings:

  1. 𝐺1=𝐺2. We call these type of pairings symmetric
  2. 𝐺1≠𝐺2, with an efficiently computable homeomorphism 𝜑:𝐺2→𝐺1
  3. 𝐺1≠𝐺2, but with no efficiently computable homeomorphism.

Comment: You may have noticed that a new term has popped up: homeomorphism. We give the definition of homeomorphism below.

Definition (Homeomorphism). Let 𝐺,𝐻 be groups. A group homeomorphism 𝜑:𝐺→𝐻 is a map that satisfies

𝜑(𝑔1𝑔2)=𝜑(𝑔1)𝜑(𝑔2),∀𝑔1,𝑔2∈𝐺

To illustrate how to use this definition, let the two groups be (𝐺,∗) and (𝐻,+). Then, the above relation becomes

𝜑(𝑔1∗𝑔2)=𝜑(𝑔1)+𝜑(𝑔2)

Pairings allow us to translate translate a hard problem from an elliptic curve group (like ECDLP) to a hard problem in a different kind of group—specifically, a multiplicative group within a finite field (a “classical” discrete logarithm problem). The key part of this is the fact that it’s in enabling cryptographic constructions that were previously impossible or highly inefficient - something which ZKPs make use of. We can demonstrate this by translating from the computational Diffie-Hellman (CDH) to Decision Diffie-Hellman (DDH) scheme.

Comment: The difference between both variants of Diffie-Hellman schemes is the underlying purpose of each variant. The CDH variant is used to securely generate a symmetric cryptographic key over a public channel, while the DDH variant is used to determine if a candidate key is the correct secret key

In CDH, imagine two parties: Max with secret 𝑎, Sara with secret 𝑏.

  1. Max and Sara both agree in a public channel, the prime group order 𝑝 and base point 𝑃.
  2. Max produces 𝑎𝑃, while Sara produces 𝑏𝑃.
  3. They exchange the values over the public channel. Max receives 𝑏𝑃, while Sara receives 𝑎𝑃.
  4. Max produces 𝑎(𝑏𝑃) while Sara produces 𝑏(𝑎𝑃). By group law, they are the same.

In DDH, we have to verify that for some candidate key 𝑐𝑃 if 𝑐𝑃=𝑎𝑏𝑃. For non-pairing friendly curves, this is considered a hard problem - but for pairing friendly curves, this become easy to verify, as we can use the pairing to check if

𝑒(𝑎𝑃,𝑏𝑃)=𝑒(𝑃,𝑐𝑃)

In fact, ZKPs use pairings in a similar manner: bilinear pairings let provers encode algebraic/witness relations as group-exponent relations and let verifiers check those relations with a small number of pairing evaluations. If this doesn’t make sense now, don’t worry. All will become clear in time.
